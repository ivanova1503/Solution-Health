# Задание 4.3. Проектирование базовых мер безопасности

**Цель:** Заложить фундамент безопасной интеграции мобильного приложения «Здоровье+» с ИТ-системами для защиты персональных и медицинских данных.

## 1. Схема аутентификации и передача токена

**Выбранная схема:** OAuth 2.0 + OpenID Connect (OIDC) с использованием JWT (JSON Web Tokens).
**Как это работает:**
1. Пациент входит в приложение по номеру телефона и SMS-коду (или паролю).
2. Сервер авторизации (Auth Server) выдает два токена: **Access Token** (короткоживущий, на 15 минут) и **Refresh Token** (долгоживущий, на 30 дней).
3. Access Token передается на бэкенд в HTTP-заголовке `Authorization: Bearer <токен>`.
4. Когда Access Token истекает, приложение использует Refresh Token для получения нового без повторного ввода пароля.

**Защита от подмены сессии (SD-007):** Короткое время жизни Access Token (15 минут) и хранение Refresh Token в защищенном хранилище устройства (Keychain на iOS, Keystore на Android) не дают злоумышленнику украсть сессию надолго.

# Политика Rate Limiting (Ограничение частоты запросов)

Для защиты API Gateway от перегрузок, DDoS-атак и парсинга базы данных (а также для предотвращения дублирования записей из-за двойных кликов) применяются следующие правила:

| Тип запроса | Лимит | Действие при превышении |
| :--- | :--- | :--- |
| **Публичный:** «Поиск врачей» (неавторизованный) | 10 запросов / минуту с одного IP-адреса | **HTTP 429 (Too Many Requests).** Ответ содержит заголовок `Retry-After` с указанием времени, через которое можно повторить запрос. При повторных нарушениях IP блокируется на 1 час. |
| **Авторизованный:** «Создание записи к врачу» | 5 запросов / минуту на одного пользователя (User ID) | **HTTP 429 (Too Many Requests) + задержка (Throttling).** Запрос обрабатывается с искусственной задержкой в 2 секунды (защита от ботов). При превышении лимита в 2 раза — временная блокировка функции записи для пользователя на 5 минут. |

# Меры по защите данных при передаче

Для защиты персональных и медицинских данных пациентов при взаимодействии мобильного приложения с ИТ-системами «Здоровья+» применяются следующие обязательные меры:

1. **Шифрование канала (TLS 1.3):**
   Все данные передаются исключительно по протоколу HTTPS с использованием TLS версии 1.3 (допускается 1.2). Устаревшие и уязвимые протоколы (SSL, TLS 1.0/1.1) отключены на стороне API Gateway.

2. **Certificate Pinning (Закрепление сертификата):**
   В код мобильного приложения «зашивается» публичный ключ или хеш сертификата нашего сервера. Если злоумышленник попытается организовать MITM-атаку (перехват трафика) с помощью поддельного сертификата, приложение разорвет соединение и не передаст данные.

3. **HSTS (HTTP Strict Transport Security):**
   Сервер API Gateway отправляет заголовок `Strict-Transport-Security`, который принудительно указывает мобильному приложению (и браузерам) использовать только HTTPS-соединение, блокируя любые попытки перехода на незащищенный HTTP.

4. **Отсутствие PII (персональных данных) в URL и логах:**
   Чувствительные данные (ID пациента, результаты анализов, номера полисов) передаются только в теле запроса (методы POST, PUT). Запрещено передавать их в query-параметрах (GET-запросах), чтобы они не оседали в логах прокси-серверов, балансировщиков и CDN.

5. **Валидация входных данных (защита от SQL-инъекций):**
   На уровне API Gateway и сервисов применяется строгая валидация всех входящих данных по схемам (OpenAPI/JSON Schema). Все запросы к базе данных используют параметризованные запросы (Prepared Statements) для предотвращения SQL-инъекций (решение проблемы INT-006).
